# المرحلة الأولى: أساس المنتج والتصميم

## ملخص المنتج

«دلّني» منصة عربية Mobile First تبدأ من كفر صقر بمحافظة الشرقية، وتساعد المستخدم على الوصول إلى التخصص الطبي الأنسب ثم الطبيب والحجز. المنصة لا تشخّص الأمراض ولا تقدم علاجًا.

## مبادئ التجربة

- العربية وRTL في جميع الواجهات.
- الهاتف هو نقطة البداية، ثم التابلت والكمبيوتر.
- مساران واضحان: البحث المباشر أو المساعدة في اختيار التخصص.
- 3D أداة وظيفية خفيفة لا عنصرًا استعراضيًا.
- لا تعرض أرقام الأطباء قبل الحجز.
- البيانات التجريبية موسومة بوضوح.
- الحالات الطبية غير الواضحة لا تُخمن؛ يُعرض مسار مساعدة آمن.

## الرحلات الأساسية

1. بحث مباشر: الرئيسية ← البحث والفلاتر ← النتائج ← الطبيب ← الموعد ← المريض ← الدفع ← مراجعة الإدارة ← التأكيد.
2. اختيار تخصص: الرئيسية ← الجسم/مكان الألم ← الأعراض ← تخصص مقترح فقط ← أفضل 3 أطباء ← جميع الأطباء.
3. انضمام الطبيب: صفحة الانضمام ← التسجيل ← رفع المستندات ← مراجعة الإدارة ← التفعيل ← إعداد المواعيد.
4. ما بعد الزيارة: حجوزاتي ← زيارة سابقة ← تقييم خاضع للمراجعة ← تحديث مبسط في «رحلتي الصحية».

## Design System المعتمد

| الدور                 | اللون                 |
| --------------------- | --------------------- |
| Primary Navy          | `#12304A`             |
| Interactive Turquoise | `#18B7B0`             |
| Page Background       | `#F5FAFB`             |
| Surface White         | `#FFFFFF`             |
| Success               | `#22B573`             |
| Warning / Destructive | يستخدم عند الحاجة فقط |

- الخط: Cairo مع بديل `system-ui`.
- الأسلوب: Medical + Futuristic هادئ، مساحات بيضاء، بطاقات واضحة، وحركة خفيفة.
- الزوايا: مستديرة ومريحة للموبايل، مع Touch Targets لا تقل عن 44px.
- الحالات الدلالية تستخدم Tokens بدل ألوان مكتوبة داخل المكونات.

## اتجاه الشعار

شعار عربي فقط: كلمة «دلّني» بخط واضح، مع دمج إشارة اتجاه بسيطة في حرف الدال أو النقطة. نتجنب السماعة الطبية والصليب والنبض التقليدي. النسخة الحالية النصية مؤقتة حتى اعتماد الرسم النهائي.

## Wireframe الصفحة الرئيسية

1. شريط علوي: العلامة، الحساب، والانضمام كطبيب.
2. Hero: الرسالة الأساسية وثلاثة مسارات رئيسية.
3. بطاقة الدليل البصري/3D.
4. التخصصات الشائعة الستة.
5. كيف يعمل دلّني؟ في ثلاث خطوات.
6. الأطباء الأعلى تقييمًا مع توضيح أن البيانات تجريبية.
7. دعوة الأطباء للانضمام.
8. تنبيه طبي وروابط قانونية وWhatsApp.

## الحالات العامة

- Loading: Skeleton يحافظ على شكل المحتوى.
- Empty: رسالة مفيدة مع الإجراء التالي.
- Error: شرح بسيط، إعادة المحاولة، والعودة للرئيسية.
- Offline: رسالة اتصال واضحة دون فقدان إدخال المستخدم.
- غير محدد طبيًا: لا تخمين؛ توجيه للتواصل للمساعدة.

## Architecture عامة — بدون Backend

- Frontend الحالي: React + TanStack Start + TypeScript + Tailwind.
- Route-based code splitting مع فصل المكونات حسب الميزة.
- طبقة بيانات مستقلة مستقبلًا عن مكونات العرض.
- نماذج الإدخال تتحقق من البيانات في الواجهة والخادم.
- Backend وقاعدة البيانات والمصادقة والتخزين والخرائط و3D وWhatsApp ستُعرض كاقتراح تفصيلي قبل تنفيذ المرحلة المختصة.

## نطاق المرحلة الثانية

- إكمال الصفحة الرئيسية Responsive.
- الحفاظ على RTL وMobile First.
- إظهار المسارات الثلاثة بوضوح.
- إضافة «كيف يعمل دلّني؟» ودعوة الطبيب والانضباط البصري على الشاشات الكبيرة.
- عدم تنفيذ البحث أو الحجز أو 3D التفاعلي قبل مراحلها المحددة.
